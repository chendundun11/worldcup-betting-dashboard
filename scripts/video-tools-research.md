# 视频工具调研

本文档用于记录 `worldcup-betting-dashboard` 与 `video-factory` 短视频链路的本地工具选择。当前不安装新依赖，不下载 GitHub 剪辑项目。

## 为什么当前不要直接安装 GitHub 剪辑项目

- 现有链路已经稳定: `export-video-package.mjs` 导出素材包，`build-douyin-video.mjs` 调用 `video-factory`，再复制到桌面输出目录。
- GitHub 剪辑项目通常会带来新的运行时、模型文件、系统依赖或平台差异，Windows 上排错成本较高。
- 当前核心需求是批量稳定生成 9:16 短视频，而不是复杂剪辑、自动字幕、AI 口播或浏览器渲染。
- 引入外部项目会增加许可、版本锁定、环境变量、缓存目录和输出文件管理风险。
- 目前更需要优化内容模板、比赛数据表达、封面可读性和预览质检，而不是替换底层生成链路。

## 可选工具

### MoviePy

- 作用: 用 Python 拼接视频、图片、音频，添加简单文字和转场。
- 适合当前项目吗: 暂时不适合。当前脚本已经用 FFmpeg 完成图片转视频、混音、截图和报告，MoviePy 主要会增加一层封装。
- Windows 安装风险: 中等。依赖 Python 包、ImageMagick 或字体处理时可能出现路径和编码问题。
- 依赖复杂度: 中等。需要 pip 安装，并继续依赖 FFmpeg。
- 是否建议现在接入: 不建议。除非后续需要更复杂的 Python 侧编排或非 FFmpeg 滤镜表达。

### auto-editor

- 作用: 自动剪掉静音、空白或低运动片段，适合长视频自动粗剪。
- 适合当前项目吗: 不适合。当前视频是图片素材包生成的 11 秒短视频，不需要静音检测或自动切片。
- Windows 安装风险: 中等。需要 Python 环境和 FFmpeg，版本兼容需要验证。
- 依赖复杂度: 中等。
- 是否建议现在接入: 不建议。当前没有长素材自动剪辑需求。

### auto-subtitle / Whisper

- 作用: 自动语音识别并生成字幕，常基于 Whisper 或相关模型。
- 适合当前项目吗: 暂时不适合。当前视频没有口播，核心信息已经通过画面文字表达。
- Windows 安装风险: 高。可能涉及 PyTorch、模型下载、显卡/CPU 性能、路径编码和缓存体积。
- 依赖复杂度: 高。
- 是否建议现在接入: 不建议。等有口播、解说音频或自动字幕需求后再评估。

### Remotion

- 作用: 用 React/Node 渲染视频，适合高度可控的动态数据视频和模板化动画。
- 适合当前项目吗: 未来可能适合。`worldcup-betting-dashboard` 已是前端项目，数据看板类视频可用 React 模板表达。
- Windows 安装风险: 中等到高。需要 Chromium/Node 渲染链路，视频导出耗时和字体一致性要验证。
- 依赖复杂度: 高。会引入新的构建、渲染和调试流程。
- 是否建议现在接入: 暂不建议。当前先保留 FFmpeg 链路，后续如果要做复杂动画模板，可单独开分支验证。

### FFmpeg 原生命令

- 作用: 视频拼接、缩放裁切、混音、截图、编码、质检。
- 适合当前项目吗: 适合。当前链路已稳定使用 FFmpeg 与 FFprobe。
- Windows 安装风险: 低。环境已经确认可用。
- 依赖复杂度: 低。只需要本地 FFmpeg、FFprobe、Node 和 Python。
- 是否建议现在接入: 已接入，建议继续使用。

## 结论

- 当前继续使用 `ffmpeg + ffprobe + 现有 Node/Python 脚本`。
- 下一步优先做内容模板优化，例如封面层级、比赛差异化文案、风险提示排版、更多比赛选择策略。
- 暂不接入复杂 GitHub 项目，不安装新依赖，不替换现有短视频生产链路。
